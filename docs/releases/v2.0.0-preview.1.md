# UniversalNotifier.NET 2.0.0-preview.1

A ground-up redesign. One API for email, SMS, mobile push, web push, Telegram, Slack, Teams, webhooks and in-app notifications; switch providers by changing configuration, not code.

> This is a preview. The API is tracked and stable in intent, but nothing has been run against live provider accounts yet (see "Known limitations"). Please try it and report what you find.

## Why 2.0

The 1.x packages could not send a message (`MailgunNotifier.FromAccount` threw `NotImplementedException`), reported most provider errors as success, and revealed every recipient to every other recipient in bulk email. 2.0 fixes these by redesigning the model, so there is no compatibility layer. See [Migrating from 1.x](../migration-from-1.x.md).

## Install

```bash
dotnet add package UniversalNotifier.NET
dotnet add package UniversalNotifier.NET.Email.Smtp   # or any provider below
```

| Channel | Package |
|---|---|
| Core, dispatcher, templates | `UniversalNotifier.NET` |
| Email | `UniversalNotifier.NET.Email.Smtp`, `.Email.Mailgun`, `.Email.SendGrid`, `.Email.Ses` |
| SMS and WhatsApp | `UniversalNotifier.NET.Twilio` |
| Mobile push | `UniversalNotifier.NET.Push.Fcm` |
| Browser push | `UniversalNotifier.NET.WebPush` |
| Telegram | `UniversalNotifier.NET.Telegram` |
| Slack, Teams, generic webhooks | `UniversalNotifier.NET.Webhook` |
| In-app inbox | `UniversalNotifier.NET.InApp` |
| Richer templates | `UniversalNotifier.NET.Templates.Scriban`, `.Templates.Fluid` |
| Background delivery | `UniversalNotifier.NET.Background` |
| Tests | `UniversalNotifier.NET.Testing` |

Targets .NET 10 (LTS) and .NET 11. .NET 8 reached end of support on 10 November 2026 and is not targeted.

## Highlights

- **Failures are results.** `SendAsync` returns a classified result (validation, configuration, permanent, transient, unknown) instead of throwing, so callers know whether repeating is safe.
- **Privacy by default.** Bulk messages are delivered individually, so recipients never see each other. Secrets, recipient addresses and message content never appear in logs or error messages. Telegram, Web Push and webhooks use their own HTTP client so secret URLs stay out of `IHttpClientFactory` logs.
- **One notification, many channels.** `Notification.To(recipient).Email(...).Sms(...).Push(...)` with templates, named providers and per-channel results.
- **Safe templates.** `{{Token}}` with HTML encoding, nested values and caching; optional Scriban and Fluid engines with execution limits, no `include`, and a plain-data model.
- **Queue friendly.** Notifications are immutable data that round-trip through JSON. The background queue is bounded with backpressure, supports idempotent submission, and drains on shutdown.
- **Observable.** Traces and metrics through `System.Diagnostics` with no extra dependency; wire them to OpenTelemetry with two `AddSource`/`AddMeter` calls. See [Observability](../observability.md).
- **Careful retries and rate limiting.** Retries are opt-in, only for failures that are safe to repeat, never after a partial success. `WithRateLimit` keeps calls under a provider's limit.
- **Engineering.** Shared provider contract suite, public API tracking, package validation, nine-plus ADRs, 400+ tests on both runtimes, and an opt-in live-test project.

## Performance

BenchmarkDotNet, short job, one machine (treat as order of magnitude): dispatching one channel about 1.1 µs and 928 B; rendering a five-token template 200 to 315 ns; queueing and reading 1000 notifications about 60 µs.

## Known limitations

- **No live provider verification yet.** Provider behavior is verified against documentation and stubs. `tests/UniversalNotifier.NET.LiveTests` (see [Live testing](../live-testing.md)) exists to change that. The Microsoft Teams Adaptive Card payload and Mailgun batch behavior are the least certain.
- Delivery receipts: signature checks follow provider documentation; the SES/SNS flow has not been run against live SNS.
- Native AOT: the core package is AOT-compatible (object data via `WithData(object)` is not; use dictionaries). Provider packages are not yet marked, and a real `PublishAot` run has not been done.
- SMTP opens one connection per send call; there is no connection pool.
- In-memory queue and in-app store lose data on restart; implement `INotificationQueue` / `IInAppStore` for durability.
- Provider options are read when the notifier is first created; changing them requires a restart.

See [Delivery guarantees](../delivery-guarantees.md) for exactly what "accepted" means per provider, and the [ROADMAP](../roadmap.md) for what is next.
